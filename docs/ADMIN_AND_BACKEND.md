# Admin And Backend

OpenChangeLog stores changelog page configuration in `backend/data/pages.json`. Releases are not duplicated: the configured PocketBase records endpoint remains the source of truth.

## Run locally

```bash
cd backend && npm run start

# In another terminal
cd frontend && npm run dev
```

Open `http://localhost:5173/admin` (or Vite's next available port) to manage pages. In production, set `ADMIN_PASSWORD` in `.env`; enter that password on the admin sign-in screen. Never use a `VITE_` prefix for this value.

## Page configuration

Each admin page has:

- Brand identity: brand name, logo URL, and website URL. The brand name and logo update the browser tab on public pages.
- Release layout: ordered blocks mapping record fields to Date, Badge, Title, Text, or Markdown content.

- `name`: public page name.
- `publicPath`: the public URL path, such as `terminal/updates`.
- `apiUrl`: the PocketBase collection-records URL.
- `markdownCss`: optional trusted CSS applied to that page's Markdown. Use “Insert starter CSS” for a page-scoped example; it is saved with that specific page.
- `isHome`: selects the page visitors see at the site root (`/`). Only one page can be the home changelog at a time.
- `introLabel`, `introDescription`, and `footerText`: customizable public copy.

Use `/admin/theme` to select a changelog page and edit its complete public theme CSS. The editor provides default CSS, live preview, save, and clear actions; each saved stylesheet belongs only to the selected page.

The page editor retains the content and route configuration.

For a page with `publicPath` set to `custom_link_changelog_page`, visitors use:

```text
https://www.example.com/
https://www.example.com/custom_link_changelog_page
https://www.example.com/custom_link_changelog_page/releasexxxx
```

The second URL is generated by clicking a release. In Admin, set **Release URL field** to the PocketBase field to expose in the URL: `id` (default), `tag`, `slug`, or `version`. Field values must be unique; for example, a record with `tag: release-2026-08` renders as `/custom_link_changelog_page/release-2026-08`.

## Production routing

Configure the reverse proxy to serve the React app for public client-side routes, including `/{publicPath}` and `/{publicPath}/{recordId}`, and proxy `/admin-api` to the Node server. The Node server listens on port `8787` by default; set `PORT` to change it.



## Release fields

The configured PocketBase collection should provide these text fields for the standard layout:

| Field | Used for |
| --- | --- |
| id | Required PocketBase record identifier and scroll-restoration target. |
| title | Release headline. |
| content | Markdown or HTML release content. |
| version | Version badge, such as v1.2.0. |
| created | Publication date, in an ISO date-time format. |
| updated | Optional last-updated date. |
| tag or slug | Optional readable, unique URL segment. Set this as Release URL field to use it in permalinks. |

The Release layout editor reads the first available record and suggests its fields. Add, remove, reorder, and map blocks to any text field. Available block types are Date, Badge, Title, Text, and Markdown content.

## First-run example

On an empty data volume, OpenChangeLog creates an editable OpenChangeLog home page with local sample releases. It demonstrates the tag, version, title, content, created, and updated fields. Edit or delete it from Admin after connecting your own collection.
